# ปีการศึกษา

Admin จัดการได้ที่ **การตั้งค่าระบบ → ปีการศึกษา** (`/apps/settings/academic-year/`)

- เพิ่มปีใหม่พร้อมวันเปิดภาคเรียนที่ 1 และ 2 ข้อมูลนี้ใช้ร่วมกับปฏิทินการศึกษา
- ปีใหม่เป็น “รอเปิดใช้” จนกว่าจะพิมพ์เลขปีและยืนยันเปิดใช้
- เมื่อยืนยัน ทุกหน้าจะใช้ปีใหม่ทันที รายชื่อนักเรียน ครู แผนก สาขา และห้องเรียนยังใช้ร่วมกัน
- เช็คชื่อหน้าเสาธง เช็คชื่อกิจกรรม เยี่ยมบ้าน คะแนนความดี คะแนนพฤติกรรม และกิจกรรมในปฏิทินเริ่มว่างแยกตามปี
- เลือกปีเดิมจากตัวเลือกปีด้านบน หรือปุ่ม “ดูข้อมูลปีนี้” เพื่อดูรายงานย้อนหลัง ปีเดิมเปิดดูได้อย่างเดียว
- การบันทึกปฏิทินของปีอื่นจะไม่เปลี่ยนปีที่ทั้งระบบใช้งาน ต้องยืนยันผ่านเมนูปีการศึกษา

## Backend scope

`academic_year_state` เก็บปีที่ใช้งานและ version ส่วนตารางบันทึกทั้ง 6 ประเภทอ้างอิง `academicYearId`.
Frontend ส่ง `X-Academic-Year` และ `X-Academic-Year-Version` โดยปีที่ไม่ระบุจะใช้ปีปัจจุบัน.
หลังเปิดปีใหม่ การเขียนบันทึกต้องส่ง version ปัจจุบัน ป้องกันหน้าที่เปิดค้างอยู่บันทึกลงผิดปี.
การอ่าน/aggregate/ความสัมพันธ์นักเรียนและคะแนนถูกกรองด้วย Prisma extension และ request context.
Database trigger ป้องกันการย้ายบันทึกข้ามปีและการแก้ไขปีเก่า รวมถึงการเขียนที่ชนกับการเปิดปีใหม่.

การเปิดปีใหม่ใช้ transaction และล็อก state เดียวกับการเขียนบันทึก พร้อม audit log.
`unscopedPrisma` ใช้เฉพาะงานจัดการปีและการตรวจสอบข้ามปีที่ฝั่ง server กำหนดไว้.

## Migration และการตรวจสอบ

Migration `20261028090000_academic_years` เพิ่มตาราง/คอลัมน์/ดัชนี โดยเก็บ ID และข้อมูลเดิมไว้.
บันทึกเดิมที่ไม่ได้ระบุปีจะอยู่ในปีที่ใช้งานก่อน migration; การเยี่ยมบ้านใช้ปีเดิมที่ระบุไว้.
ไม่สร้างวันเปิดเทอมย้อนหลังขึ้นเอง หากปีเก่าไม่มีปฏิทินจะแสดงว่าไม่มีข้อมูลปฏิทิน.

สำรองฐานข้อมูลและตรวจ SQL ก่อน deploy เสมอ สำหรับฐานข้อมูล legacy ที่ใช้ migration helper
ให้ตรวจ `prisma/deploy-migrations.ts --check-only` ก่อน แล้วเปิด
`NKTC_ALLOW_REVIEWED_LEGACY_MIGRATIONS=true` เฉพาะ migration ที่ตรวจแล้ว.
ไม่ reset ฐานข้อมูลหรือแก้ประวัติ migration เดิม.

ทดสอบ lifecycle ด้วยฐานข้อมูลสำเนาที่ชื่อขึ้นต้น `nktc_academic_year_test_`:

```bash
cd backend-elysia
ACADEMIC_YEAR_TEST_DATABASE_URL=... bun test src/__tests__/academic-years.integration.test.ts
```

ชุดทดสอบนี้เปิดปีใหม่จริงในฐานข้อมูลทดสอบ จึงห้ามใช้กับฐานข้อมูลใช้งานจริง.
ครอบคลุมข้อมูลว่างปีใหม่ รายชื่อร่วมกัน การดูย้อนหลัง การเขียนแบบ read-only
คะแนนที่อยู่ใน nested relations, concurrent requests, stale version และการยืนยันซ้ำพร้อมกัน.
